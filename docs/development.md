# Development and verification

Open the project by selecting `pom.xml` in IntelliJ's Open dialog. Choose **Open as Project**, trust your local checkout, wait for Maven import, and select JDK 17 or later in Project Structure → Project SDK. The launcher can install a JDK in `.runtime/jdk-17.0.20.1+1`; select that folder if you have no other JDK. Run `engine.Launcher` with argument `serve` and set the working directory to the repository root.

The launcher works without an IDE. Windows PowerShell 5.1 is sufficient; PowerShell 7, Node and Python are not required for a basic debate. Set `PARLIAMENT_MANAGED_JAVA=1` for a test that bypasses installed Java and uses the checksum-pinned local JDK.

For frontend boundary changes, run the relevant optional Node checks: `node scripts/verify-browser-imports.cjs`, `node scripts/verify-file-decoding.cjs`, `node scripts/verify-browser-integers.cjs` and `node scripts/verify-browser-dates.cjs`. They execute actual frontend functions with controlled DOM/network fixtures and never call models. The replay-date checks preserve supplied epoch metadata and require readable presentation outside the browser Date range; they do not change or validate the backend's exact stored timestamps.

Use `mvnw.cmd verify` on Windows or `sh mvnw verify` on Unix. All model calls in tests must be mocked or use the fixed demonstration. Java source/tests use `src/main/java` and `src/test/java`; the plain frontend stays in `web`. Provider, prompt and grounding files are read from the project root. Build and runtime output are ignored.

The base JAR is recreated whenever Maven packaging runs, before shade bundles dependencies. This follows the pinned [JAR Plugin3.4.2 forceCreation guidance](https://maven.apache.org/plugins-archives/maven-jar-plugin-3.4.2/jar-mojo.html#forceCreation): repeated packaging must not reuse a previously postprocessed JAR as its input. Dependency versions are unchanged; the launcher still bypasses Maven for an unchanged completed build. `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify-repackaging.ps1` checks this offline in a space-path fixture, using a cached JDK/Maven and `.maven-cache` (or `-RepositoryCache ABSOLUTE_PATH`). It injects synthetic stale output entries and requires two repackages to remove them without changing source or deleting outputs, then runs a synthetic packaged main. It never starts the application or models and retains logs/results under `target/repackaging-*`.

Local LLM setup is implemented by `ManagedOllama` / `OllamaInstaller`, with official version/archive pins in `OllamaPackage`. Routine tests use tiny packages, loopback HTTP and fake processes; see [local LLM setup](ollama-setup.md) for the user workflow and acceptance limits. To check that the shaded JAR includes archive readers and zstd JNI, run `engine.application.OllamaPackageSmoke` with classpath `target/test-classes;target/virtual-parliament.jar` (Windows) or `target/test-classes:target/virtual-parliament.jar` (Unix) after `verify`, passing a new directory under `target/`. The smoke extracts synthetic ZIP/gzip/zstd files and executes no runtime/model. `OllamaBrowserFixture ISOLATED_ROOT PORT` with the same classpath provides developer-only synthetic setup/generation for browser QA; keep its root under `target/` and stop it when finished. It never uses owner run data or a real Ollama executable.

For deliberate genuine Windows runtime acceptance, `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify-ollama-runtime.ps1` runs the opt-in `OfficialOllamaSmoke` after compilation/packaging. It creates a space-path fixture and a child-only test profile, downloads the official pinned archive through the shared setup job, checks empty-cache service readiness/reuse and closes the owned service. It never downloads weights, generates text or runs as part of JUnit. `-ResumeFixture ABSOLUTE_PATH` checks warm restart/reuse of an existing fixture. Preserve its result/log/process/stop files on interruption; stop signals cancel the durable job and let the application close its runtime. Keep genuine runtime evidence separate from routine fake-provider results.

`scripts/runtime.ps1` and `run.sh` pin Adoptium Temurin 17.0.20.1+1 archive URLs and SHA-256 values obtained from the [official Adoptium API](https://github.com/adoptium/api.adoptium.net/blob/main/docs/cookbook.adoc). Download to a partial file, verify, then extract into a unique staging directory. The [Apache Maven wrapper](https://maven.apache.org/tools/wrapper/index.html) is adapted file by file from the retained reference, preserving its license and pinned distribution checksum.

Initial downloads need network access to GitHub, Maven Central and Adoptium. Re-running a failed setup reuses completed downloads; unverified partial files are never executed. No installation changes the machine-wide PATH or Java installation.

Incomplete Java/Maven extraction directories are preserved beside the replacement rather than selected or nested into a new install. Java caches need both java and javac; Maven caches need the wrapper's executable. Downloads still require checksum verification before extraction. The Windows wrapper handles ordinary cache directories without assuming a symlink target. Windows launchers and guided stdin/stdout use UTF-8, including Māori text and supplementary Unicode characters.

Optional NLP setup uses `scripts/nlp-runtime.ps1` / `scripts/nlp-runtime.sh` to recover uv separately from dependency synchronization. A completed archive is reused only after checking its pinned checksum. Staged extraction records the archive and executable SHA-256 identity in `uv.bootstrap.sha256`; reuse checks that identity without executing an incomplete binary. A legacy install without this marker, a missing executable or a changed executable is preserved under `uv-incomplete-*` before replacement. The dependency sync remains locked, application-local and explicit; previously installed model extras are retained.

Run `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify-nlp-bootstrap.ps1` for offline Windows recovery checks using an already cached official uv archive. It checks spaces, missing/truncated executables, cache reuse, rejected corrupt/partial downloads and setup argument selection. Run `sh scripts/verify-nlp-bootstrap.sh` for small portable archive and setup-wiring fixtures. That check passed under Git Bash on Windows; it does not establish official Unix binary execution, native Linux/macOS or pristine-OS setup. Fixtures/results remain under ignored `target/nlp-bootstrap-*` / `target/nlp bootstrap portable.*`. Neither harness installs packages, downloads models or calls providers.

`scripts/verify-delivery.ps1` constructs an isolated tracked-file ZIP, tests Windows PowerShell5.1 with built-in-only PATH and a path containing spaces, exercises the batch launcher and real guided stdin, checks optional NLP/local-LLM absence, bundled ZIP/gzip/zstd readers and JNI, backend ownership, restart/build reuse and incomplete-cache recovery. The archive smoke uses tiny synthetic packages and never executes a model/runtime. It retains fixtures/results in ignored `target/delivery-*`. `-UseCachedJavaArchive` avoids a repeated Java download while still verifying the archive; `-ResumeFixture ABSOLUTE_PATH` continues an existing fixture inside this project's target directory. A resumed result records that fact and does not prove a fresh download. See [interface-parity.md](interface-parity.md) for operations and evidence limits. These host-isolation checks do not replace pristine-OS or native Unix verification.
