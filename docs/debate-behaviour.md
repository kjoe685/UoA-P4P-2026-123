# Targeted engagement and behavioural validation

Each scheduled speech and interjection receives an editable `prompts/EngagementCue.txt` alongside its ordinary turn cue. The scheduler chooses the latest other-party speech or interjection on the current topic as its reply target. Chair events remain in the full public transcript but are not mistaken for a member's claim. Own position references include the recipient's opening and two most recent contributions on the same topic, with duplicates removed. A new topic has no inherited target or position references until contributions exist there.

The cue uses stable public IDs to locate the existing transcript entries. It asks for a specific response, continuity with prior positions, and an explicit public reason when qualifying, revising or conceding a claim. It does not classify an utterance as a challenge or force a concession. The model still receives the full public transcript; the pointer list adds focus without deleting evaluator evidence. Cue instructions ask agents to attribute claims naturally rather than read internal IDs aloud.

Only the assigned agent's private strategy prompt contains its tactic. The strategy files now ask for observable diversion, distortion or procedural demands tied to public contributions; they never enter another agent's instructions or the shared engagement cue. Ordinary agents receive no notice of hidden assignments. The persona/grounding/strategy and every editable cue are captured at sitting start, and public exports do not contain these private resources.

Browser Advanced configuration, guided CLI advanced assets and `cli assets validate|save` expose the engagement template through the same resource validator. It requires exactly `TOPIC_ID`, `TARGET_TURN_ID` and `OWN_TURN_IDS` placeholders. Changing it affects new sittings without recompilation; existing sittings retain their captured text.

Controlled tests cover topic transitions, interjection targets, opening/recent position references and a synthetic concession scenario. Actual mock HTTP tests verify the target and own-history references are transmitted without another agent's private assignment. These checks establish cue assembly, scheduling and privacy. They **do not establish improved live-model behaviour**. Human review must still compare actual claims, responsiveness, repetition, reasoned concessions and observable tactics across fixed scenarios. More interjections alone are not evidence of success.
