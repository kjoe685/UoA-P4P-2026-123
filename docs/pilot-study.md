# Human-review pilot data and local reports

The browser's **Human-review pilots** panel, guided CLI choice 17 and `cli pilot` commands share one application service. Imports are immutable owner datasets in `runs/pilots/<UUID>.json`. They are separate from debate transcripts, agent prompts and public exports. Classifiers receive item IDs and text; DeBERTa also receives the explicit policy proposition. Gold labels, reviewer pseudonyms, source identity and split assignments never enter classifier requests.

## Prepare genuine material

The developer helper reads the same checksum-pinned ParlSpeech V2 NZ source described in [grounding.md](grounding.md). It excludes the installed grounding corpus by both source row and full-speech hash, excludes chair speeches and selects one verbatim sentence per speech, with duplicate text removed. Source sentences are 50–500 characters and 10–80 words; the latest-date shortlist is deterministic. Supply a proposition that a human curator will assess, rather than inferring a gold stance from party identity:

```text
python scripts/extract-hansard.py --pilot-proposition "The House should build more public housing." --pilot-target-id housing --pilot-count 240 --grounding data/hansard/excerpts.json
```

The default candidate is `.runtime/hansard/pilot.candidate.json`. Extraction is explicit and does not import it. It records the source DOI, file hash, source speech/debate IDs and full-speech hash. `sourceDebateId` combines date and agenda hash; this is a source grouping, not a verified parliamentary sitting identifier. No sentiment, stance, reviewer or split is generated by the helper. The latest-date sampling is convenient review material, not a representative research sample. Curators must inspect source context and targets.

Import the candidate and select **Prepare 200 unlabelled items**, or use:

```text
run.cmd cli pilot import .runtime/hansard/pilot.candidate.json
run.cmd cli pilot prepare SOURCE_PILOT_ID 123
run.cmd cli pilot show PREPARED_PILOT_ID review.json
```

Preparation excludes source speeches used in the **currently installed** grounding corpus. It shuffles eligible items with the saved seed, selects 200, then shuffles their distinct source-debate IDs and assigns the first quarter of debates to calibration and the rest to held-out review. Both groups are nonempty and no source debate crosses them. Item counts can be uneven because entire debates stay together. A prepared file records the input dataset hash, seed, exclusion-set hash and selection-policy version. Labels and reviewer fields remain blank, including when preparing from a previously reviewed source. Fewer than 200 eligible distinct items is an error; no data is duplicated to reach the minimum.

## Review and import

Schema version 1 requires `evidenceType`, `source` and `rows`; `preparation` is optional. A short unreviewed illustration is:

```json
{
  "schemaVersion": 1,
  "evidenceType": "unreviewed",
  "source": {
    "title": "Source title",
    "doi": "10.1234/SOURCE",
    "url": "https://example.org/source",
    "fileSha256": "64 lowercase hexadecimal characters"
  },
  "rows": [{
    "id": "sentence-1",
    "sourceDebateId": "source-debate-1",
    "sourceSpeechId": "source-speech-1",
    "sourceSpeechSha256": "64 lowercase hexadecimal characters",
    "text": "Verbatim source sentence.",
    "target": {"id": "housing", "proposition": "Build more public housing."},
    "split": "",
    "sentiment": "",
    "stance": "",
    "reviewer": ""
  }]
}
```

The hash placeholders must be replaced with real hashes; this illustration is too small to prepare or score. Imports accept 1–1000 rows and reject duplicate IDs/normalised text, inconsistent speech hashes/debate groups, inconsistent target propositions, unknown fields and credential-bearing source URLs. Genuine-source declarations require a DOI and an HTTPS source URL. The importer validates their structure; it does not independently authenticate arbitrary uploaded text or hash claims.

Human reviewers should work from the prepared file, inspect its context and proposition, and fill **both** labels for every item: sentiment `negative`, `neutral` or `positive`, and stance `support`, `oppose` or `unrelated`. Add a reviewer pseudonym, keep the debate-separated split and preparation metadata, then change `evidenceType` to `human_reviewed`. Import this reviewed file as a new immutable dataset. Reviewed datasets require at least 200 fully labelled items and both nonempty splits. Reviewer declarations are not an audit of actual review; agreement/adjudication and sampling validity need a separate research protocol.

Use `synthetic_fixture` only for explicitly artificial software fixtures. Those also need complete labels and splits, and their reports carry a persistent software-only interpretation. They cannot be prepared into a human-review pilot. `unreviewed` data cannot be scored. The application has not collected genuine human labels or established model accuracy.

## Score and interpret

Set up the desired local methods first, select them in the browser or pass method IDs:

```text
run.cmd cli pilot list
run.cmd cli pilot evaluate REVIEWED_PILOT_ID vader-sentiment,cardiff-sentiment,deberta-stance
run.cmd cli jobs
run.cmd cli job JOB_ID
run.cmd cli report JOB_ID pilot-report.json
run.cmd cli cancel-job JOB_ID
```

Unix uses `sh run.sh cli` with identical arguments. The job captures the dataset, local-analysis configuration, model settings and grounding exclusion set at submission. Reviewed imports and scoring reject overlap with any current grounding speech before constructing a classifier. Exclusion does not cover historical corpora that are no longer installed; retain study-specific exclusion material separately.

Each method analyses each item independently. Exact evidence, offsets, label/score semantics and model revision are validated. An item split into multiple analysis chunks becomes `pilot_unit_segmented`, preserving its evidence while counting the prediction as a failure; unvalidated aggregate predictions are never substituted. Successful and failed observations are saved after each item. Cancellation retains completed items and discards the unfinished one. Restart marks pending jobs interrupted without resuming inference. Stored reports reopen without starting a classifier.

Reports show each method and split independently: completed/planned counts, macro-F1, confusion matrix, coverage, failures, abstentions, mean and nearest-rank p95 latency, and per-item evidence/provenance. Sentiment and stance use their respective gold labels. Macro-F1 averages the three declared classes, giving an absent class zero; failed and abstained predictions remain false negatives instead of disappearing from the denominator. Coverage counts predictions with a declared class; latency includes completed failures and abstentions. Interrupted reports describe only committed observations, with planned counts visible. There is no combined score, debate-quality score, research pass threshold or inferred suitability. Calibrate only on calibration data and interpret held-out results under the actual human-review protocol.
