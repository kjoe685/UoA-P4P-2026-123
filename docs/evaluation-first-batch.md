# First live evaluation batch

Requested 2026-10-09 Pacific/Auckland: one repetition of three topics at 0, 10 and 100 Hansard excerpts per party, five rounds and all five parties, separately generated by GPT-6 Luna and cached Ollama Qwen3 8B. This is 18 fresh one-topic debates and 450 ordinary speeches. The topics and stance propositions are frozen in each batch manifest. All private adversarial strategies are NONE and both interruption probabilities are zero.

For a topic, speaking order is identical across generators and grounding levels. The base order is Labour, National, Green, ACT, NZ First, rotated by topic index and later repetition index. All five parties speak once per round. Each topic has a fresh transcript. Hansard selection uses the application's frozen first-N-in-corpus-order policy; the 10-excerpt selection is a prefix of the 100-excerpt selection. Hansard is a historical style treatment, not current policy evidence.

Generation settings: `gpt-6-luna`, temperature 0.6, reasoning `none`, maximum 4096 completion tokens, 180-second timeout; `qwen3:8b`, temperature 0.6, no reasoning/think override, maximum 4096 completion tokens, 600-second timeout. Qwen therefore retains model-default thinking. The local context allocation is 131072 with flash attention and q4_0 KV cache, serial inference and cloud disabled; this allocation accommodates the application's deliberately conservative UTF-8 context admission estimate. Record observed inventory digest, cache bytes, runtime version and actual completion coverage instead of assuming availability or context success.

Use a fixed common judge for both generators: `gpt-6-luna`, temperature 0, reasoning `none`, maximum 8192 completion tokens, strict JSON schema, at most one repair (two calls total per debate). Report consistency, logical reasoning, responsiveness, relevance and rhetorical tactics separately on the existing 0–4 rubric. Higher rhetorical-tactics scores mean more disruption. No combined or normalized score is computed. Judgments describe each participant within the topic, not independent per-speech rubric scores. Local VADER and Cardiff sentiment and DeBERTa stance produce separate sentence observations, uncertainty/abstention and captured model provenance.

An application provider wrapper records usage, request hashes, completion status and latency without prompts or credentials. Before each paid dispatch it durably reserves an input bound of serialized UTF-8 request bytes plus 4096 protocol tokens, and the full output cap. It refuses requests whose bound reaches 272000 tokens and refuses total reservations exceeding USD4.50. Conservative short-context prices of USD0.275 input / USD1.10 output per million cover fast processing, cache-write and regional uplifts. Reported usage releases unused reservation; missing usage and provider failures retain the full amount. Standard-price estimates use USD0.10 / USD0.50, ignore cache discounts and are estimates rather than an account invoice. [Official Luna model and prices](https://developers.openai.com/api/docs/models/gpt-6-luna), checked 2026-10-09. No platform spending-limit setting is changed.

The driver calls the existing `DebateApplication` and its production providers, persistence and evaluation services. It freezes study resources in an ignored study application directory and never alters active root settings. Original credentials are read by the provider factory, remain outside the study and are never copied or exported. Saved private setup, public transcripts/reports and operational/usage records occupy distinct directories. A prepared manifest is required; an already-started batch cannot automatically restart inference. Inspect partial results before any explicitly requested recovery. The driver never reruns a failed generation. The existing transport may retry a rejected HTTP429 once within its request deadline; it never retries successful/ambiguous billed responses.

`scripts/prepare-evaluation-study.py REPOSITORY BATCH --repetitions 1` prepares the exact matrix. Values 3 and 5 are supported only for later explicitly authorized collections. Compile `scripts/CollectEvaluationStudy.java` against the packaged application, run its `self-test` and `self-test-matrix` modes with fake providers, then use `collect REPOSITORY BATCH` only for an authorized live batch. The fake matrix is isolated and labelled synthetic; it is never added to the research workbook.

Workbook data uses stable batch/cell/run/repetition/topic/provider/model/grounding/party/turn/metric keys, typed numeric observations and explicit status fields. Blank scores mean missing or insufficient observations, never zero. Sentence chunks and five-round/party scores remain distinct observation grains. New provider/repetition batches can be appended by regenerating the workbook from selected completed manifests and reports; existing run IDs are deduplicated. One repetition supports descriptive exploration only. Speeches within a debate are clustered observations, and automatic rubric validation does not establish human scoring or research accuracy.
